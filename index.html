    V22 · CLIENT-SPECIFIC ACCESS CONTROL

    Security & Access Readiness

    A practical readiness checklist for client isolation, least-privilege access, private documents and safe rollout. The checklist runs locally in this browser; it does not inspect or change your Supabase configuration.

    Pre-production checklist

    Access-control readiness

    Tick each item only after it has been completed and verified in your own staging environment.

    0 of 6 checks marked complete

    V22 security model

    • Staff: can read records in their organisation according to their role.
    • Clients: can read only projects linked to their assigned client record.
    • Milestones: visible only when attached to an accessible project.
    • Documents: clients can see metadata marked client-visible and attached to their client/project.
    • Billing: client reads are restricted to their linked invoices and payments.

    Opportunities, tasks, and internal messages remain staff-only in this starter policy set.

    Rollout sequence

    1. Back up the staging database and inspect existing policies.
    2. Apply supabase/v22_client_access_control.sql.
    3. Assign a trusted admin process to set each profile's client link; do not let users set their own role or organisation.
    4. Run cross-client negative tests for every table and storage path.
    5. Use a trusted Edge Function to verify document visibility before issuing a signed URL.

    What this upgrade does not do

    It does not apply migrations remotely, assign client identities automatically, create an Edge Function, or prove that your deployed policies are correct. The current V21 browser download handler should not be treated as a client authorization boundary. Review it before allowing client downloads.

    Never place a Supabase service-role key in the browser or portfolio files.

    Important: SQL policy changes can lock out users or expose records if existing permissive policies remain. Apply in staging first, inspect all policies, and have a qualified reviewer validate the final policy set before production use.
